Connect any app that writes logs.

RootCause accepts HTTPS JSON batches and newline-delimited JSON. Each app uses a private bearer key. The server redacts common secrets again before storage.

1. Direct HTTP (any language)

Send one event or a batch of up to 100. Keep the key in a server-side environment variable.

curl -X POST "$ROOTCAUSE_URL/v1/logs" 
  -H "Authorization: Bearer $ROOTCAUSE_API_KEY" 
  -H "Content-Type: application/json" 
  -d '{"logs":[{"level":"WARN","service":"orders","message":"Database operation took 900 ms","durationMs":900}]}'

2. Vector log forwarder

Use Vector's HTTP sink with newline-delimited JSON. Normalize source fields to message, level and optionally service, timestamp, duration_ms, and status_code. Common aliases such as log, severity, and time are accepted.

[sinks.rootcause]
type = "http"
inputs = ["your_normalized_logs"]
uri = "${ROOTCAUSE_URL}/v1/logs"
method = "post"
batch.max_events = 100
batch.max_bytes = 240000

[sinks.rootcause.auth]
strategy = "bearer"
token = "${ROOTCAUSE_API_KEY}"

[sinks.rootcause.encoding]
codec = "json"

[sinks.rootcause.framing]
method = "newline_delimited"

[sinks.rootcause.request]
headers.Content-Type = "application/x-ndjson"

3. Fluent Bit HTTP output

Forward structured records with JSON-lines encoding. Inject the key from your container or secret manager; never commit the real value.

[OUTPUT]
    Name          http
    Match         *
    Host          your-rootcause-host.example
    Port          443
    URI           /v1/logs
    TLS           On
    Format        json_lines
    Json_Date_Key timestamp
    Json_Date_Format iso8601
    Header        Authorization Bearer REPLACE_WITH_PRIVATE_APP_KEY
    Header        Content-Type application/x-ndjson

4. Standard HTTPS clients

All languages can call the same endpoint. Queue logs asynchronously in your application so monitoring does not block request handling.

NODE.JS
await fetch(`${process.env.ROOTCAUSE_URL}/v1/logs`, { method:"POST", headers:{Authorization:`Bearer ${process.env.ROOTCAUSE_API_KEY}`,"Content-Type":"application/json"}, body:JSON.stringify({logs:[{level:"ERROR",service:"checkout",message:"Database timeout"}]}), signal:AbortSignal.timeout(3000) });
PYTHON
requests.post(os.environ["ROOTCAUSE_URL"]+"/v1/logs", headers={"Authorization":"Bearer "+os.environ["ROOTCAUSE_API_KEY"]}, json={"logs":[{"level":"ERROR","service":"checkout","message":"Database timeout"}]}, timeout=3)

Limits and responses

Batch: 1–100 events. HTTP body: 256 KiB. Responses are 202 accepted, 401 invalid or revoked key, 402 monthly plan limit reached, 413 payload too large, and 429 rate limited. Timestamps more than 24 hours from server time are replaced with receipt time. Start with WARN and above if your app emits a high volume of INFO logs.

Rotate keys from your workspace; rotation immediately invalidates the old key. Never expose keys in browser code, public repositories or logs.
