Quick start

  1. Create an API key in . Name it after your app, like my-store-api. Copy it immediately; it is shown once. Use one key per app.
  2. Save ROOTCAUSE_API_KEY and ROOTCAUSE_INGEST_URL in your server environment. Never put a key in source code, GitHub, a browser or a mobile app.
  3. Send a test error using the curl example below.
  4. When monitoring launches, check that the test arrived in Monitoring → Logs.
  5. Send real errors and warnings from your app using one of the examples.
  6. When monitoring launches, choose email, Slack or Telegram alerts in Monitoring → Alerts.

Good habits
  1. Send logs in the background with a roughly five-second timeout. Catch failures so logging cannot crash your app.
  2. Send errors and warnings first. Debug logs add noise and use your monthly limit.
  3. Keep passwords, tokens and personal information out of logs.
  4. Send one clear message per event and include the full stack trace for errors.
  5. Test after logging changes. For a 429 or 5xx response, wait briefly and retry once.
